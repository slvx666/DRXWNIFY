# Drxwnify 2.3.0 — что нужно знать при переносе (Rust / Linux / iOS)

Этот файл для ИИ-агента, который переносит версию 2.3.0 Android-приложения на другую платформу.
Здесь записано, **как должно работать** и **какие решения уже приняты после проверки** — чтобы не
повторять ошибки, которые на Android уже нашли и исправили. Источник истины — код Android
(`android/`), пути ниже относительно него. Если этот файл и код расходятся — прав код.

Не меняй принятые решения «на свой вкус» (размеры, тайминги, поведение): почти каждое значение
ниже подобрано по прямой просьбе владельца после проверки на телефоне.

---

## 1. Самое важное (то, на чём легко ошибиться)

1. **Spotify Web API `me/top/*` не работает — и ждать бесполезно.** На любой запрос
   `GET api.spotify.com/v1/me/top/tracks|artists` приходит `429` с каждый раз разным
   `Retry-After` (8 с, 55 с, 56 с…), даже после честного ожидания. Причина: токен веб-плеера
   принадлежит общему client id, квота которого исчерпана всеми сразу (с ~15.12.2025 Spotify
   режет Web API для токенов официальных клиентов). **Не добавляй ретраи/ожидания — используй
   GraphQL `userTopContent`** (раздел 4).
2. **Статистика приложения ≠ статистика сервисов.** «Статистика» в Интеграциях и «Итоги месяца»
   считаются **только по истории прослушиваний в самом приложении** (об этом есть строка на
   экране). На страницах Spotify/Яндекса показывается **только то, что отдаёт сервис** — итоги
   приложения туда не вставлять.
3. **У Spotify нет личного числа прослушиваний** трека/исполнителя. Есть только место в топе.
   (`playcount` у трека в GraphQL — это мировые прослушивания, не пользователя; в итоги их не
   ставить.) Поэтому в итогах Spotify строки «N раз» нет.
4. **ВК — полноценный каталог наравне со Spotify и Яндексом**, а не «источник аудио». Модели те же.
5. **Основной аккаунт не меняется при перелогине.** Только первое подключение (правила в разделе 3)
   и ручной выбор пользователя.

## 2. Идентификаторы (маршрутизация по id)

Каталог определяется **по префиксу id**:

| Что | Формат | Каталог |
|---|---|---|
| трек Яндекса | `ym_<raw>` | Яндекс |
| альбом/исполнитель/плейлист Яндекса | `ym_<raw>` (`YandexIds.album/artist/playlist`) | Яндекс |
| трек ВК | `src:VK:<owner>_<audio>[_<key>]` | ВК |
| альбом или плейлист ВК | `vk_<owner>_<id>[_<key>]` (в ВК это всё «плейлисты») | ВК |
| исполнитель ВК | `vkar_<id>` | ВК |
| «Моя музыка» ВК | `vk_liked` | ВК |
| всё остальное | id Spotify | Spotify |

Трек ВК имеет **тот же id, что и трек ВК, найденный поиском источников** — история, лайки, загрузки
и аудио у него общие, откуда бы он ни пришёл. Альбомы и страница исполнителя в ВК есть только у
официальных релизов; у пользовательской загрузки их нет (`catalog/VkCatalog.kt`).

## 3. Основной аккаунт, вкладки, лайки (`catalog/MainAccount.kt`)

- Основной аккаунт: Spotify, Яндекс или ВК. От него зависят медиатека, главная, рекомендации,
  цвет библиотеки и профиль, который видят друзья.
- **Первое подключение** делает аккаунт основным, если: это Spotify (всегда), или основного ещё
  нет, или это тот же сервис (`defaultMakeMain`). **Перелогин основной не меняет.**
- Смена основного (`choose`): ничего не удаляется; сбрасываются кэши каталога, главная помечается
  устаревшей и пересобирается (`HomeFeed.markStale`), кэш профиля Spotify, друзьям публикуются
  лайки и профиль нового основного.
- Остальные аккаунты — **отдельные вкладки библиотеки**, по умолчанию **выключены**, включаются на
  странице аккаунта (`accountTab_<SOURCE>`).
- Куда уходит лайк (`LikeMode`, по умолчанию `MAIN_AND_SOURCE`):
  - `MAIN_ONLY` — только в основной;
  - `MAIN_AND_SOURCE` — в основной и туда, откуда трек;
  - `ALL` — во все подключённые аккаунты.
  Трек в чужом каталоге ищется по названию, исполнителю и длительности (`catalog/CrossCatalog.kt`);
  чего там нет — остаётся лайком в приложении с пометкой.

## 4. Топы Spotify через GraphQL (`spotify/.../Spotify.kt`, `SpotifyHashProvider.kt`)

Это ровно то, что показывает профиль на open.spotify.com («топ этого месяца»).

- **Запрос:** `POST https://api-partner.spotify.com/pathfinder/v2/query`, тело как у остальных
  GraphQL-вызовов приложения (persisted query):
  ```json
  {
    "operationName": "userTopContent",
    "variables": {
      "includeTopArtists": true,
      "topArtistsInput": { "offset": 0, "limit": 50, "sortBy": "AFFINITY", "timeRange": "SHORT_TERM" },
      "includeTopTracks": false,
      "topTracksInput":  { "offset": 0, "limit": 50, "sortBy": "AFFINITY", "timeRange": "SHORT_TERM" }
    },
    "extensions": { "persistedQuery": { "version": 1, "sha256Hash": "<hash>" } }
  }
  ```
  Для треков — наоборот (`includeTopTracks: true`). `limit` до 100.
- **`timeRange`:** `SHORT_TERM` (4 недели), `MID_TERM` (полгода), `LONG_TERM` (всё время).
  Внимание: **`MID_TERM`, не `MEDIUM_TERM`**. Проверено на телефоне: `LONG_TERM` отдаёт другие данные,
  чем `SHORT_TERM`, — работает.
- **`sortBy`:** `AFFINITY` (как у веб-плеера). Есть ещё `LAST_PLAYED`, `PLAY_COUNT` — не используем.
- **Ответ:** `data.me.profile.topTracks` (`__typename == "TrackPageV2"`, `totalCount`,
  `items[].data` с `__typename == "Track"`) и `data.me.profile.topArtists`
  (`"ArtistPageV2"`, `items[].data` с `__typename == "Artist"`: `uri`, `profile.name`,
  `visuals.avatarImage.sources[]`). Трек разбирается обычным разбором GraphQL-трека
  (`uri`, `name`, `artists.items[].profile.name`, `albumOfTrack.coverArt.sources`, длительность).
- **Хеш** на 14.11.2026: `61b7353d3625780022dbc63d459eb64cd609e7e5e2a820f9160d65030efe2e15`.
  Хеши меняются при обновлениях веб-плеера, а в общий реестр хешей
  (`francescograzioso.github.io/Meld/spotify-gql-hashes.json`) `userTopContent` **не входит**.
  Поэтому при ответе `412` / `PersistedQueryNotFound` хеш достаётся из веб-плеера:
  1. `GET https://open.spotify.com/` (браузерный User-Agent) → найти `web-player.<hash>.js`;
  2. скачать `https://open.spotifycdn.com/cdn/build/web-player/web-player.<hash>.js`;
  3. найти id чанка: `(\d+):"xpui-routes-profile"`, затем его хеш файла: `[,{]<id>:"([0-9a-f]{8})"`
     (может быть несколько совпадений — пробовать по очереди, часть даёт 404);
  4. скачать `.../xpui-routes-profile.<8hex>.js` и найти
     `"userTopContent","query","([0-9a-f]{64})"`;
  5. сохранить новый хеш и повторить запрос один раз.
- Другие места, которые раньше звали REST `me/top` (рекомендации, профиль вкуса), автоматически
  получают данные через эту же функцию.
- **Риск, не проверен:** создание плейлиста в Spotify идёт через REST `POST me/playlists`. Если он
  тоже упрётся в общий 429 — нужен GraphQL-аналог. На Android это отдельно не проверялось.

## 5. ВК как каталог

- Альбомы, исполнители, плейлисты и «Моя музыка» — в библиотеке, как у Spotify/Яндекса.
- У любого ВК-трека работают «К альбому» и «К исполнителю» (в т.ч. для загрузок, которые находятся
  через поиск официального релиза).
- Плейлист ВК — это альбом, если он похож на альбом по трекам: классификация в фоне, не больше 200
  штук, пауза 400 мс между запросами (`VkCatalog.classifyInBackground`).
- Альбомы ВК в библиотеке отсортированы по числу треков.
- Когда список ВК заканчивается, музыка **продолжается похожими треками** (как у других каталогов).
- Кэши: библиотека и страницы — 5 мин, рекомендации — 3 ч.
- **Отвергнуто владельцем:** отдельный раздел «рекомендации ВК» на главной — не добавлять.

## 6. Перенос из другого аккаунта (`playback/AccountTransfer.kt`, `playback/RemotePlaylists.kt`, `ui/.../AccountTransfer.kt`)

- Экран выбора: вкладки «Плейлисты / Альбомы / Треки», поиск, «выбрать все», счётчики, одна кнопка
  «Перенести в <основной>». Открывается сразу на списках.
- **Альбом, который уже есть в основном аккаунте, отмечен зелёной галочкой «уже в <сервис>».**
  Сопоставление нестрогое (обязательно повторить именно так, иначе галочки пропадают у реальных
  совпадений, например «Artist - Title (2024)» в названии плейлиста ВК):
  - ключ = `fold(artist) + "|" + foldTitle(title)`;
  - если в названии есть ` - ` / ` – ` / ` — ` и часть до тире совпадает с исполнителем (или
    исполнителя нет) — она становится исполнителем, остаток названием;
  - исполнитель — первый из `", "`, `" & "`, `" feat. "`;
  - `fold` = нижний регистр, выбросить всё кроме букв и цифр;
  - `foldTitle` дополнительно убирает скобки `(...)`/`[...]`, слова
    `deluxe|edition|remaster(ed)|expanded|version|ep|single|lp` и годы `19xx/20xx`;
  - совпадение: названия равны, либо (оба ≥ 5 символов и одно начинается с другого); исполнители
    равны или один содержит другой; если исполнителя нет у одной стороны — нужны равные названия.
- Списки кэшируются: в памяти 15 мин и на диске (`transfer_<key>.json`) — показываются сразу,
  свежие подгружаются следом.
- Перенос медленный, по одному элементу (пауза 700 мс, до 5000 треков): альбом ищется в каталоге
  основного и сохраняется, трек ищется и лайкается, плейлист копируется в приложение (играет сразу)
  и затем создаётся в основном аккаунте в фоне.
- Создание плейлиста в аккаунте (`RemotePlaylists`): задачи на диске, шаги CREATE → FILL → DONE,
  id плейлиста сохраняется сразу после создания, позиция — после каждой пачки (повтор не создаст
  второй плейлист и не добавит пачку дважды). Пачка 20 треков, 400 мс между поисками, 4 с между
  пачками, 6 с между задачами. API: Spotify `POST me/playlists`; Яндекс
  `users/<uid>/playlists/create` (private) и `.../change-relative`; ВК `audio.createPlaylist` /
  `audio.addToPlaylist`.
- Импортированные плейлисты (файлы, ссылки, другой аккаунт) запоминаются и предлагаются для создания
  в основном аккаунте, когда он появится.

## 7. Итоги (история) — `ui/screens/MonthReviewStory.kt`, `StoryAudio.kt`

Полноэкранная история как Spotify Wrapped. Один и тот же движок для трёх видов итогов:
итоги месяца приложения, итоги Spotify (за выбранный период) и итоги Яндекса (по лайкам).

### Управление
- Листается **только свайпами** (тапы по краям не листают). Удержание пальца — пауза.
- Сверху: полоски страниц, тонкий ползунок громкости, пауза, закрыть.
- Пауза истории **не останавливает музыку**.
- Полоска новой страницы пустая с первого кадра (без мигания полной полоски прошлой страницы).
- На последней странице: «Поделиться» (PNG карточки), «Сохранить», «Смотреть снова».
- Пока история открыта, основная музыка приложения на паузе; после закрытия продолжает, если играла.

### Страницы итогов приложения (длительности, мс)
`hello 4700` → `minutes 8000` → `day 8000` (если есть) → `topTrack 11000` → `topTracks 12000` →
`topArtist 11000` → `topArtists 12000` → `genres 11000` → `card` (без таймера).
Приветствие: текст целиком появляется за ~2,1 с, пустая пауза после него короткая.

### Страницы итогов сервиса
`hello` («Твои итоги в <сервис>: <период>») → `likes 8000` (только Яндекс) → `topTrack` →
`topTracks` → `topArtist` → `topArtists` → `card`. Без минут, дней и жанров. Период в заголовках
списков: «Твои треки за всё время», «Твои исполнители за последние 4 недели», у Яндекса «по лайкам».
**Не писать «месяца»** в итогах сервиса. Числа: у Яндекса «в лайках: N», у Spotify — никаких.

### Анимации
- `Appear(delay, fromRight, duration)`: элемент **с самого начала занимает своё место** (ничего не
  сдвигается, когда появляется следующий), проявляется и доезжает последний кусок пути (справа на
  35 % ширины или снизу на 36 dp), масштаб 0,97 → 1. Кривая «Settle» `cubic-bezier(0.22, 1, 0.36, 1)`.
- Страницы с одним треком/исполнителем: две подводки (0,1 с и 1,2 с), сам трек/исполнитель — 2,8 с.
- Порядок появления в списках (`revealTimes`): сначала мелкие места снизу вверх, начиная с 600 мс,
  каждые 70 мс; затем +350 мс; затем топ-5 с 5-го по 1-е с промежутками 500/600/700/800/900 мс —
  первое место появляется последним.
- Переход страниц: медленный кроссфейд с лёгким зумом и сдвигом по направлению листания.

### Раскладка списков (проверено владельцем на телефоне 1080×2436)
- Списки выровнены по верху, отступ сверху 68 dp (у остальных страниц 96 dp), снизу 40 dp.
- Колонка на всю высоту, свободное место распределяется **между строками** (`SpaceBetween`),
  а не остаётся внизу.
- **Треки:** 21 шт. Топ-5 крупно (обложка 54 dp, номер 24 sp, название + «исполнитель · N раз»),
  места 6–21 — две колонки по 8 (обложка 36 dp, 5 dp между строками).
- **Исполнители:** 11 шт. Топ-5 с убывающим размером (фото 96/84/74/66/66 dp, имя 25/22/20/18/18 sp),
  места 6–11 — две колонки **3 слева и 3 справа**, строкой: номер, круглое фото 48 dp, имя, «N раз».
  Отвергнуто: ряд из 5 маленьких кружков без читаемых имён.
- Обязательно показывать число прослушиваний у каждого (в итогах приложения).

### Звук (`StoryAudio`)
- Отдельный плеер, созданный музыкальным сервисом приложения (те же источники, что у основного
  плеера: ВК, YouTube, кэш), очередь не трогается. Обычный «голый» плеер не умеет играть URI
  приложения — на Android из-за этого история была беззвучной.
- Трек начинается с **трети длительности** (если длина неизвестна — после загрузки).
- **Разгон громкости с 0 % от начала страницы до полной к моменту, когда появляется название
  трека** (~2,8–2,9 с). Если звук ещё грузится, разгон начинается, когда он реально пошёл, но
  заканчивается вовремя (минимум 600 мс). Кривая разгона мягкая: `smoothstep(x) * x`.
- Смена трека: затухание 700 мс. Тот же трек на следующей странице просто продолжается.
- После страницы жанров трек **не обрывается**: последняя страница продолжает тот же трек до конца.
- **Громкость по умолчанию = громкость приложения × 0,8** (чуть тише). Дальше её меняет только
  ползунок сверху.
- Трек, которого нет в базе приложения (Spotify/Яндекс в итогах сервиса), находится так же, как
  обычный трек каталога (поиск аудио по названию/исполнителю/длине).

## 8. Статистика

### «Статистика» в Интеграциях (`ui/.../AppStatsScreen.kt`)
- Итоги месяца за последние 6 месяцев (только месяцы с прослушиваниями) — **каждая строка
  кликабельна** и открывает историю; справа стрелка в круге. Не делать одну кнопку «Открыть итоги»
  только у первого месяца — это вводит в заблуждение.
- Числа: минут в этом месяце, минут всего, прослушиваний, исполнителей, любимых треков, плейлистов,
  друзей, сообщений написано/получено.
- Подпись: «Считается по прослушиваниям в этом приложении — без истории Spotify, Яндекса и ВК».
- **Кэш в памяти**: повторный вход показывает всё сразу; прошлые месяцы не меняются, числа тихо
  пересчитываются. Пока итоги считаются впервые — заглушка-скелетон.
- Прослушивание засчитывается по правилу `Listening.counts(playTime, duration)`.

### Итоги месяца (данные, `catalog/ServiceStats.kt` → `MonthReview`)
- Топ-21 трек, топ-11 исполнителей, минуты, прослушивания, новые исполнители, самый активный
  день и минуты в нём, любимый час, жанры (теги Last.fm исполнителей), жанр первой/второй половины
  месяца, песни топ-жанра.
- Предлагается один раз — при первом открытии приложения в новом месяце (через 4 с), если в прошлом
  месяце были прослушивания.

### Страница статистики сервиса (`ui/.../ServiceStatsScreen.kt`, маршрут `account_stats/<SOURCE>`)
- **Spotify:** вкладки «4 недели / 6 месяцев / Всё время», топ исполнителей и треков, кнопка
  «Смотреть итоги» (история за выбранный период). Кэш на диске — сутки.
- **Яндекс:** всего лайков, лайки по месяцам (12 столбиков), исполнители с наибольшим числом лайков
  с **их собственными фото** (запрос `artists/<id>/brief-info`; обложка трека — только запасной
  вариант), кнопка «Смотреть итоги». Кэш на диске — сутки (`yandex2.json`).
- **ВК:** статистики нет — сервис ничего не отдаёт.

## 9. Импорт и мелочи 2.3.0

- **Ссылки Яндекс Музыки в импорте:** хосты `music.yandex.*` (.ru, .com, .by, .kz, .uz):
  `/album/<id>`, `/users/<owner>/playlists/<kind>` (если owner — логин, uid берётся из ответа API),
  `/playlists/<uuid>` (через `playlist/<uuid>`). Плейлист по ссылке получает **своё название**.
- Кнопка импорта активна сразу; пустое название подсвечивается красным.
- Альбомы в библиотеке: сортировка по году выпуска и фильтр по году.
- Окно Интеграций прокручивается.

## 10. «Вместе» (друзья, Nostr) — `friends/`

- Друзья отсортированы по активности.
- «Слушает сейчас» гаснет сам: статус считается живым, только если последнее слово было «играет» и
  трек ещё не должен был закончиться: `now <= at + (duration - position) + 3 мин`. Работает и с
  друзьями на старых версиях — от отправителя ничего нового не нужно.
- **Аватарки друзей хранятся локально** (имя + картинка), потому что релеи со временем выкидывают
  старые события профиля → у друзей пропадали аватарки.
- **Свой профиль публикуется заново раз в 3 дня**, чтобы релеи его не потеряли.
- **NIP-42 (AUTH, kind 22242):** часть релеев (например relay.damus.io) отвечает
  `CLOSED ... auth-required` на запросы данных друзей. Нужно: запомнить `challenge` из `["AUTH", …]`,
  на `auth-required` подписать событие kind 22242 ключом профиля, отправить `["AUTH", event]`, а
  после `OK` на это событие повторить закрытые подписки. При переподключении challenge сбрасывается.
